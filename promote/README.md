# Promote — by Techverse

A working multi-business booking, events and ticketing application. Each business has a branded website and installable PWA. MC Henry’s profile uses the supplied materials; historical flyers are portfolio images, not invented upcoming events. Real receiving accounts must be added by their owners.

## Run locally

Requires Node.js 24.14 or newer.

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

Open **http://localhost:3000**. Complete **/setup** once to create the Techverse administrator. There are no default credentials. That administrator can manage MC Henry immediately and create an owner invitation for Henry when ready.

For development, `npm.cmd run dev` starts the API on port 3000 and Vite on port 5173. You can also run `node server/index.mjs --port 4173` to use a different preview port. Local first-run setup is allowed only from the same computer. Production setup requires the secret code in `.data/bootstrap-code.txt`.

Optional scripted provisioning reads `ADMIN_EMAIL` and `ADMIN_PASSWORD` from environment variables: `node --env-file-if-exists=.env scripts/setup.mjs`. Never commit real passwords or the `.data` directory.

## Included behaviour

- Ten professions with their own workflows, public work formats and booking packages. A business can combine professions. Techverse can add professions and choose a workflow blueprint in Platform settings. Services have editable inclusions, duration, pricing and relevant booking questions.
- Self-service registration and administrator-created accounts. Profiles start as drafts. Automatic unique business slugs and branded PWA manifests/icons.
- Business branding, image uploads, gallery, social links, contacts and publication controls. Upload a square photo/logo as the app icon for the best home-screen result.
- A full colour system derives the website’s surfaces, borders, readable text, buttons and workspace colours from the business’s chosen accent. Choose a dark or light website appearance. The branding studio previews changes before saving. App chrome and manifest colours follow the saved theme.
- Public image uploads show a local preview, are oriented and optimised for web delivery, and can be reused from a business-specific uploads library. Upload buttons support keyboard use. Existing uploaded pictures remain available. Payment screenshots remain in their separate, private storage flow. Portfolio pictures open in a full-image viewer with arrow-key and swipe navigation.
- Brand partnerships support images, flyers and MP4/WebM video (images up to 8 MB, videos up to 40 MB). A business can create drafts, schedule features, set priority, change media, pause, archive and restore. Techverse can enable or disable this capability like other features.
- A desktop partner feature has a reserved side rail; phones receive a compact announcement with a picture. Only one feature is shown at a time. Visitors may make it compact or hide it, and their preference is remembered. Booking, checkout, private payment and ticket pages do not display partner ads.
- Videos are muted by default, with explicit play/pause and sound controls. Playback pauses when hidden, collapsed or removed, and muted automatic playback respects reduced-motion/data-saving preferences. Observed views and interested devices are deduplicated per feature and day. Partner features do not automatically send marketing push notifications.
- Bookings collect contact details and service-specific answers. Availability must be accepted before payment instructions appear. Quotes include amount, currency and payment deadline. Accepted dates reserve the calendar; overlapping accepted dates are rejected. Owners can block time manually.
- Bank/MoMo receiving accounts per business. Every paid transfer requires a valid image screenshot and matching amount/currency. Proof is private and server-authorised. A screenshot never automatically marks a payment as received.
- Free and paid event ticket types. Free tickets are issued immediately; paid tickets follow screenshot approval. Atomic capacity reservations prevent overselling. Pending paid orders reserve tickets for 30 minutes; submitted screenshots retain the reservation while under review.
- Unique QR tickets, phone-camera scanning, image scanning and QR-text entry. Online atomic check-in rejects repeat use. Guests retrieve tickets through private links and can print/save them; no fan account is required.
- Unlimited owner-managed staff invitations. Permissions cover bookings, payment reviews, events, check-in, content, notifications, insights, staff invitations, event planning and private client deliveries. Event restrictions apply to planning boards as well as ticket operations. Staff cannot change receiving accounts. Revocation takes effect on the next request without reinstalling the app.
- Public event announcements, publish/change/cancellation alerts, automatic reminders within 24 hours of an event, and private work alerts. Standard encrypted Web Push with persistent VAPID keys, retry jobs and expired-subscription removal. Local dashboards use Server-Sent Events; Netlify deployments refresh visible pages every 15 seconds. Web Push runs independently.
- Actual visitor-device activity, observed install signals, active installed-app devices within 30 days, stored notification subscriptions, ticket counts and verified receipts by currency. These are not exact phone install/uninstall counts or unique people.
- Techverse-wide account access, feature checkboxes, optional public directory, verification, suspension, plan assignment, recurring invoices and individual bills.
- Global billing starts **off**. Plans can be prepared without charging. Activation applies assigned invoices and recurring plans. Each bill has a due time and a hold time. Screenshot submission keeps the hold until Techverse confirms receipt. Access returns automatically when no overdue unpaid invoice remains; a separate manual suspension is preserved.
- Billing holds stop new business activity while preserving private records, customer ticket retrieval and scanning of already-issued tickets. The owner can still pay the platform invoice. Zero-cost plans do not create payable holds. Recurrence does not back-bill the free/paused period before billing activation.
- Private screenshots never enter the service-worker cache. The PWA supplies a branded offline page, cached static assets and a user-controlled update notice so unsaved work is not interrupted. Sending requests, retrieving private records and checking in tickets require internet. Public event subscriptions and private staff alerts are managed separately; leaving work alerts enabled does not override a visitor's public-event preference.

## Tools for each profession

Open **My professional studio** in the business workspace. Only enabled tools for the business's selected professions appear. Work starts as a draft; empty sections are omitted from the website. Existing profile details and customised services are preserved when these tools are added.

The public website follows the business's **main profession**, chosen in **Profile & branding**. New accounts can choose it during registration or administrator onboarding. The first selected profession is stored as the main one; existing accounts keep their current first profession until the owner changes it. Additional professions retain their public sections and services. Changing the main profession preserves custom headlines, saved work, packages and receiving accounts.

The main profession sets the homepage order, navigation, main action, descriptive wording and visual treatment. DJs and musicians lead with listening; photographers with their portfolio; videographers with films; guides with tour departures; MCs and comedians with performance work; organisers and promoters with actual upcoming dates. Creator collaborations and media kits have their own sections. Navigation links appear for available public content and enabled services, and work can be opened directly from its cover image. Empty calendars are omitted from the homepage; event notification signup remains available. Combined professions share one brand, with separate labelled sections and navigation that also works from booking pages.

| Profession | Professional tools |
| --- | --- |
| MC / event host | Hosting reels and event cases, event formats, languages, hosting style and stage requirements; wedding and corporate enquiry packages. |
| DJ | Real audio uploads, covers, ordered tracks, collections, genres and equipment requirements; DJ-specific booking questions. |
| Promoter | Promotion and brand campaign cases with highlights and deliverables; promotion briefing packages, alongside the existing partner features and ticket tools. |
| Event organiser / planner | Private event checklists, task status, responsible people, due dates, notes and run of show; public event lineup and ticket tools. |
| Tour guide | Tour departures with itineraries, stops, durations, meeting point, map, languages, inclusions and practical details; free or paid tour places with QR tickets. |
| Content creator | Content collaborations, channel links and creator-provided audience figures, deliverable packages and private client content review. |
| Musician / performer | Audio releases and collections, live performance films, lineup and technical rider; live and acoustic booking packages. |
| Comedian | Stand-up/show clips, audio, performance languages, audience suitability and stage requirements; set and comedy-hosting packages. |
| Photographer | Public photo albums, coverage packages and private client galleries with favourites, saved selections, final submission and original download controls. |
| Videographer | Public films/showreels, production formats and packages; private film review with feedback, change requests, reopened review and final approval. |

Audio accepts MP3, M4A, OGG and WAV files up to 25 MB. Visitors explicitly start playback; only one audio/video player plays at a time. Professional videos accept MP4/WebM up to 40 MB. Larger mixes and films can link to an external full release. Uploaded audio is not automatically distributed to music services.

Published tour departures reserve the guide's calendar. Overlapping departures and accepted service bookings are rejected, including when accepting an enquiry received before the departure was published. Tour capacity and paid transfer proof use the existing ticketing workflow. Tour announcements and reminders use the notification system.

Private client files use a separate authorised storage table and do not appear in the public uploads library. Private photos can be up to 20 MB, review films up to 40 MB; large final files can use an external HTTPS delivery link. Client links expire and can be revoked or replaced. The secret is exchanged from the URL fragment into an HTTP-only scoped session cookie; private media is never cached by the service worker. Anyone holding the private link can access its delivery, so share it directly with the intended client.

When photo downloads are disabled, only a resized preview is served to the client. Download controls do not provide DRM or prevent saving media that can be viewed. Client selections and review decisions persist, submitted reviews lock until reopened, and changing files or workflow reopens review. Submitted client reviews notify permitted delivery staff; linked event-plan notices respect the staff member's assigned events. No client/fan account is required, and links are copied for manual sharing; no automatic email or WhatsApp delivery is configured.

## Domains and separate installations

`BASE_DOMAIN` must be a domain Techverse owns, without `www` (for example, `promote.yourdomain.com`). Configure wildcard DNS **and wildcard HTTPS** for `*.BASE_DOMAIN` to your hosting ingress. Then a new business slug resolves automatically; no per-business code deployment is needed.

On a tenant host such as `mchenry.BASE_DOMAIN`, `/` opens Henry’s profile and his manifest has the correct brand and identity. Separate origins give businesses separate storage, permissions and app installations. `mchenry.localhost:3000` can be used for local separate-origin tests in supporting browsers. `/p/mchenry` is also provided for the single-host local preview; multiple profiles under that shared origin share browser permissions, so use distinct tenant hosts in production.

Custom domains can be added when the feature is enabled. Ownership is checked against a `_promote.<hostname>` DNS TXT record. Verification does not configure your hosting provider’s domain ingress or TLS: connect both before sharing that address. New `.com` registration/purchase is **not** wired to a registrar in this build; an available domain must be registered before it can be connected. No domain has been purchased or claimed.

Choose the final address before asking fans to install. Moving an existing PWA to another origin can require a fresh installation and notification permission.

## Notifications and production setup

Copy `.env.example` to `.env` and configure the actual domain, host/port, data path and Web Push contact email. Generated VAPID keys are stored persistently in the database; back them up with the database and keep them stable. The server must be able to reach browser push services over HTTPS.

On iPhone/iPad, Web Push requires a supported OS/browser, home-screen installation, and an explicit user gesture to grant notification permission. Android/desktop support varies by browser. Phone Focus modes, revoked permissions, connectivity and browser policies affect delivery time. Do not promise guaranteed instantaneous arrival. Test real iOS and Android devices on the final HTTPS address before launch. Lock-screen push delivery was not verified on a physical phone during the local build.

Private booking/order pages update their state when open; customers keep their private links. Automatic email, WhatsApp messages and SMS are not configured. Invitations are generated as copyable links; no message is sent automatically. Refunds and disputes are handled directly with the organiser; no payment-provider automation or refunds are implied by a screenshot review.

For password recovery, the server operator can set `RECOVERY_EMAIL` and `RECOVERY_PASSWORD` in the private environment and run `node --env-file-if-exists=.env scripts/reset-password.mjs`. This revokes all sessions for the account. Remove those recovery values afterwards. An already signed-in user can change their own password from Security.

## Deployment and storage

For Netlify with Supabase Postgres and Storage, see [NETLIFY.md](NETLIFY.md). Production API and maintenance functions share the persistent cloud database; direct uploads preserve existing media limits. Credentials stay in Netlify Functions variables. Free quotas and inactivity rules apply.

The local installation uses SQLite and .data/uploads. A standalone container can use a mounted persistent volume. Keep private data, payment proofs, backups and real environment files out of source control.

The included Dockerfile builds the frontend and runs as a non-root user. Mount `/app/data`, configure `BASE_DOMAIN`, terminate HTTPS at a reverse proxy, forward the original Host header, and set `TRUST_PROXY=1` only for a controlled single reverse proxy. Production sets secure session cookies; plain HTTP login is intentionally unsuitable. Use the bootstrap code from the mounted data volume to claim the first administrator.

The running process executes billing, expiry, reminders and push retries every 15 seconds. Persisted due work is checked after a restart. Set a process restart policy and monitor `/api/health` and scheduler logs. A stopped server cannot send notifications while stopped. Back up the data volume regularly.

Create a consistent database snapshot plus uploaded files with:

```powershell
node --env-file-if-exists=.env scripts/backup.mjs
```

Backups contain private customer/payment data. Store them securely outside public assets. To restore, stop the application, restore the snapshot as `DATA_DIR/promote.sqlite` and the accompanying `uploads` directory, then restart. Keep existing keys and domain settings. Avoid using source-control archives as data backups.

## Validation

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
npm.cmd run test:experience
npm.cmd run test:professions
npm.cmd run test:site-flow
```

API tests use isolated databases under `.data/tests` and verify the full booking/payment/ticket/billing flow and authorisation boundaries. Browser tests use local Microsoft Edge via Playwright, isolated data, desktop and 390px phone viewports, real form submissions, QR ticket generation and overflow checks. Reports and screenshots are written to `test-results`. If Edge is unavailable, install a Playwright-supported Chromium browser and adjust the launch channel in `tests/browser.mjs`.

The experience suite additionally checks real upload previews and saved media delivery, purple/blue/coral themes and readable button text, desktop side-rail geometry, compact phone announcements, remembered visibility preferences, streamed WebM playback, tap-to-enable sound, and clear booking screens at 360px. Nested upload dialogs preserve the editor draft. Gallery viewing and long business names are checked at phone, tablet and desktop widths. Temporary refresh failures preserve open drafts; an access-denied response clears private workspace content. API tests sample 4,096 colours in both appearance modes for text, button and hover contrast. The suite uses generated test media in an isolated database; no real business is assigned an invented partner campaign.

The profession suite checks all ten profession workspaces, real WAV playback, media collections, hosting reels, creator media-kit editing, public albums, private photo selections, film change requests and approval, tour itineraries and reservations, planning checklists, and small-phone layouts. API coverage also verifies tenant isolation, workflow permissions, private preview/original access, expired/replaced/revoked client links, feature flags, tour capacity and transfer proof. Test media is generated only inside isolated test databases. The website flow suite checks role-specific homepage order and navigation, main profession changes, preservation of additional roles and custom copy, feature gating, and layouts at 360, 390, 768, 1024 and 1440 pixels. Colour checks evaluate both solid buttons and transparent text links against the rendered background.
